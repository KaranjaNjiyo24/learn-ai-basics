Shamba Bora: app map

A short guide to where things live in the app, so you know where to start when you want to change something.

What the app is

Shamba Bora gives a sugarcane farmer a low-to-high estimate of tonnes per acre for his own land, then optionally what that harvest could earn in Ksh. It runs entirely in the browser: there is no server of our own and nothing is saved between visits. The only outside pieces are the weather and place-name services.

Main pieces: the page (index.html, with three views Home, Did you know?, My farm), the coordinating file (js/app.js), the calculations (js/estimate.js, js/money.js, js/note.js), the outside lookups (js/location.js, js/weather.js), and the sample data (data/reference-data.js, data/facts.js).

One action, followed through

The action: he taps Show my estimate with a new price entered.

A 3-stop route (reference route)

This is a reference route to reuse. Search for the names, since line numbers drift as the code changes.

Stop 1: where the tap lands

js/app.js, search function handleSubmit. It reads the fields, checks them with validateAll, asks "are you sure?" for unusual values, then calls runEstimate, which fetches the weather and calls showResult. It coordinates; it does no maths.

Stop 2: where the maths happens

js/estimate.js, search export function estimate. It picks a baseline range for the variety, works out one factor each for pH, N, P, K and rainfall, multiplies them into combined, and applies that to the range. The numbers it uses are in data/reference-data.js and are labeled sample data.

Stop 3: where the income comes from

js/money.js, search export function money. It multiplies the tonnes range by the new price and compares it with last season's price and spending. showMoney in js/app.js puts its sentences on the screen. Blank money fields add nothing.

A practice to reuse

Write what "working" looks like, then run known numbers to check it

The PRD states observable results for money: devpost/prd.md, under "Money (optional, built last)", says blank money fields must not affect the yield estimate and that a new price must produce an income range. While building js/money.js, running it in Node with a bad price (a negative number and plain text) printed "NaN" in the income sentences. That was caught by running known inputs before anyone saw the page, and it was fixed first. Because each result was written down as something you could observe, the problem was easy to spot.

Next time, with any agent: ask for each feature's expected result in plain words and one concrete example input, then run that example yourself before moving on.

Run it again

From the project folder, run python3 -m http.server 8000, then open http://localhost:8000. Location and the JavaScript modules need a web server, so opening index.html directly will not work.
