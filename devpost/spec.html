Shamba Bora — Technical Spec

Spec draft — for your review

How it works, in plain language

A small website that runs entirely in the browser: no server of our own and no database. The browser provides the date picker and the "Allow location?" prompt. Open-Meteo, a free weather service, is the only outside piece. A labeled sample reference table plus a short calculation turns his inputs into a low-to-high range. A log writes technical messages to the browser's developer console (F12) so errors can be checked.

Architecture

Step through the journey

Stack and how to run

  • Plain HTML, CSS, JavaScript (ES modules). No framework, no build step.
  • Run: python3 -m http.server 8000, then open http://localhost:8000.
  • Open-Meteo (weather, geocoding) and the browser Geolocation API. URLs and terms unverified; check first in the build.

Look and feel

#964B00 text, borders, buttons · #008000 animation and main action · #FFFFFF background. Square corners, Times New Roman, flat, no gradients. (The colors on this review page are softer on purpose.)

Components

intro.js — animation and fact pop-up

CSS/SVG growth animation, then one verified fact with a close button. PRD: Opening animation and "Did you know?"

validate.js — checks

Each field is ok, missing, or unusual; unusual shows "That looks unusual — are you sure?" PRD: Farm details, States and Boundaries

location.js — location

Browser prompt first; if refused, a typed place name looked up by geocoding (my recommendation, awaiting your agreement). PRD: Location and weather

weather.js — weather

Daily rainfall and temperature from planting date to today; totals the rainfall and averages the temperature. Failure returns typical values with isLive: false. PRD: Location and weather

estimate.js — the range

Baseline low–high for the variety → one factor each for pH, N, P, K, and rainfall → multiply the factors → apply to baseline → widen if weather isn't live. PRD: Yield estimate

note.js, money.js, log.js

Rule-written planning note; income range and price comparison (built last); console logging with timestamps. PRD: Planning note, Money, States and Boundaries

Failure modes, simplifications, open issues

Failure modes
  • Location refused → type a place name
  • Place not found → "try a nearby town"
  • Weather fails → "try again" or continue on typical conditions, wider range
  • Odd or blank input → friendly check
Simplified
  • Sample reference table instead of a trained model
  • Nothing saved between visits
  • Typed soil values, not OCR
  • Rule-written note, not AI
  • Local run and recording, not deployed
Open issues
  • Verify Open-Meteo URLs, terms, and recent-data approach
  • Choose sample numbers, labeled SAMPLE
  • Your task: 3–5 verified facts with sources
  • Place-name fallback and local server run: your agreement
